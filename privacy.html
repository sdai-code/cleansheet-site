Privacy Policy — CleanSheet for Google Sheets™

Effective Date: November 11, 2026 · Last Updated: November 18, 2026

Google Workspace APIs & Google API Services — Limited Use Compliance Disclosure:
The use of raw or derived user data received from Workspace APIs will adhere to the Google User Data Policy, including the Limited Use requirements. CleanSheet’s use and transfer to any other app of information received from Google APIs will also adhere to the Google Workspace APIs User Data and Developer Policy, including all Limited Use and AI/ML model training restrictions.

1. Data Access — Minimal OAuth Permissions & What Data We Access

CleanSheet is engineered on a strict least-privilege architecture. Our add-on manifest (appsscript.json) requests only two narrow Google OAuth scopes, plus standard non-sensitive Google Workspace Marketplace identity scopes:

  • https://www.googleapis.com/auth/spreadsheets.currentonly — Allows CleanSheet to read and update cells only in the single active spreadsheet where you explicitly launch the CleanSheet add-on. CleanSheet has zero access to your Google Drive or any other spreadsheets in your account.
  • https://www.googleapis.com/auth/script.container.ui — Allows CleanSheet to render its 300px sidebar interface inside Google Sheets via SpreadsheetApp.getUi().showSidebar().
  • userinfo.email & userinfo.profile — Standard non-sensitive Google Workspace Marketplace sign-in scopes included by Google Cloud Console for add-on installation. CleanSheet does not store or use your personal profile or email address for marketing.

Exact Google User Data Accessed:

  • Raw Google User Data: Only the cell values, header names, and cell background colors of the active sheet tab or sub-range that you explicitly inspect or clean while the CleanSheet sidebar is open.
  • Aggregated / Anonymized Data: A temporary anonymized Apps Script user key (Session.getTemporaryActiveUserKey()), subscription tier (Free vs. Pro), monthly AI row credit count, and SHA-256 content hashes used to deduplicate identical AI normalization lookups.
  • APIs Never Accessed: CleanSheet never requests or accesses Google Drive, Gmail, Google Chat, Google Meet, Google Photos, YouTube, Health, or Data Portability APIs.

2. Data Use & Prohibited Data Uses

  • How We Use Google User Data: Raw spreadsheet cell values are used strictly to generate live Dry-Run Previews and execute the specific data-cleaning operations you trigger in the sidebar (Deduplicate Rows, Combine Duplicate Rows, Clean & Split Columns, 1-Click Undo, and the optional AI Normalizer). Aggregated/anonymized quota counters are used solely to enforce Free (100 AI rows/mo) and Pro (15,000 AI rows/mo) usage limits.
  • Prohibited Data Use Guarantee: Raw, derived, and aggregated/anonymized Google user data is never used for any purpose other than providing or improving user-facing features of CleanSheet. We strictly prohibit using Google user data for targeted advertising, personalized ads, retargeting, creditworthiness or lending determinations, or user profiling.

3. Data Transfer & Third-Party Sharing

  • 100% In-Browser Deterministic & Fuzzy Processing (Tools 1–3): When you run Deduplicate Rows, Combine Duplicate Rows, Split Names, Split Text, Phone Number Formatting, Email Cleaning, Domain Extraction, URL Tracking Parameter Stripping, Date Formatting, Change Case, or Whitespace/HTML Trimming, your spreadsheet cells are processed entirely inside your web browser and Google Apps Script. None of this data is transferred to external servers or third parties.
  • Optional AI Normalizer (Tool 4 — Third-Party AI Inference Subprocessor): Only when you explicitly click the run button in the optional AI Normalizer tool are the non-empty cells of your selected column and your selected prompt/preset transmitted over encrypted HTTPS/TLS to our stateless Google Cloud Run endpoint (cleansheet-backend) and forwarded to the OpenAI API (third-party LLM inference provider) solely to return normalized text values back to your sheet.
  • Billing Processor (Stripe): Subscription checkout and billing portal sessions are processed by Stripe. CleanSheet never transfers any spreadsheet cell data to Stripe.
  • Prohibited Data Transfer Guarantee: Raw, derived, and aggregated/anonymized Google user data is never sold, rented, or transferred to data brokers, advertisers, or any third parties for any purpose other than executing the user-requested feature, in strict compliance with the Google User Data Policy Limited Use requirements.

4. AI/ML Model Training Restrictions & Limited Use Compliance

  • Prohibited AI/ML Model Training: CleanSheet never uses raw, derived, or aggregated/anonymized Google Workspace user data to develop, train, fine-tune, or improve any internal, foundational, or general-purpose AI/ML models.
  • Prohibited Transfer to Third-Party AI/ML Services for Training: CleanSheet never transfers Google Workspace user data to any third-party AI/ML service that uses that data to train or improve its AI/ML models. Under OpenAI’s API data usage policies, data submitted through the OpenAI API is not used to train or improve OpenAI models.
  • Affirmative Limited Use Statement: “The use of raw or derived user data received from Workspace APIs will adhere to the Google User Data Policy, including the Limited Use requirements.”

5. Data Protection & Security

  • Encryption in Transit: All data transmitted between the Google Sheets sidebar iframe, Google Apps Script, our Google Cloud Run service, and the OpenAI API is encrypted in transit using industry-standard HTTPS / TLS 1.2+.
  • Least-Privilege Isolation: By scoping permissions strictly to spreadsheets.currentonly, CleanSheet is cryptographically restricted by Google’s OAuth boundary to the single spreadsheet tab opened by the user.
  • Stateless Compute & Signed Tokens: Our Cloud Run backend processes AI normalization batches statelessly in memory without writing raw spreadsheet cells to disk or databases. Requests between Apps Script and Cloud Run are authenticated using HMAC-SHA256 signed session tokens.

6. Data Retention & Deletion Policies

  • Raw Spreadsheet Cells (Zero External Retention): Raw spreadsheet cells sent to the optional AI Normalizer are processed in memory only for the duration of the HTTP request and are discarded immediately once the normalized values are returned to your sheet.
  • 1-Click Undo Backups: Backup snapshots are stored solely as hidden tabs (_CleanSheet_Backup_*) directly inside your own active Google Sheet—never on external servers. They are automatically deleted when you click Undo, or you can delete them manually inside Google Sheets at any time.
  • Saved Scenarios & Quota Metadata: Saved Scenario presets are stored in Google Apps Script’s per-user PropertiesService.getUserProperties() container and can be deleted in 1 click from the sidebar. Anonymized quota counters (Session.getTemporaryActiveUserKey(), tier, and credit count) and SHA-256 lookup caches are retained only to maintain your active subscription and quota state.
  • How to Revoke Access or Request Data Deletion: You can delete all saved scenarios and backup tabs inside the sidebar at any time, revoke CleanSheet’s OAuth permissions via your Google Account Permissions page, or email sdai.code@gmail.com to request complete deletion of all associated account and quota records (processed within 7 calendar days).
